# Contributing

1. Create a branch for the change.
2. Keep node-specific changes in the corresponding source file or future node directory.
3. Do not commit Wi-Fi credentials, Blynk tokens, access PINs, build output, or device-specific logs.
4. Document hardware, baud-rate, and dependency assumptions in the same change.
5. Run a credential scan and the narrowest available build or hardware check before opening a pull request.

Until build projects and automated tests are added, include manual verification steps in the pull request description.
